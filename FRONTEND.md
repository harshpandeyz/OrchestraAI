# FRONTEND.md — OrchestraAI Console

## Product thesis
- OrchestraAI is an autonomous work environment with a transparent runtime underneath: TASK → PLAN → EXECUTION → DECISIONS → EVIDENCE → RESULT → CONTINUE/REVIEW. The center workspace answers outcome first (what was accomplished, can I trust it, what changed); raw telemetry is one tab away, never the headline.
- Visual hierarchy: task → agent-working state → accomplishments → trust/evidence → changes → decisions → cost → internals. The run header carries title + one status pill + journey strip + a secondary resource line; full model/budget/token/latency detail lives in the inspector.

## Architecture
- `frontend/` — Vite + React 18 + TypeScript. No chart/map libs; all visualizations are div/SVG bars (offline-safe, no fake telemetry).
- `backend/` — zero-dependency Node HTTP runtime implementing the contracts in `ARCHITECTURE.md` and `CONTRACTS.md`; the console runs end-to-end over REST + authenticated SSE without a second frontend-specific API.
- Types in `src/types.ts` mirror `CONTRACTS.md` verbatim and are the only schema.

## Component structure
- `lib/semantics.ts` — the ONLY event→UI translation layer: `humanizeEvent` (technical codes → human copy), `liveActivity`, `toMilestones` (trace → PLAN/CONTEXT/MODEL/ACTION/VERIFY/RESULT rail with burst grouping), `provenanceLabel` (OBSERVED/PROVIDER/ESTIMATED/DEMO/UNKNOWN), `trustGrounding`. Pure + unit-tested. Components must use it, never raw `event.type ===` checks.
- `components/execution/ExecutionTimeline.tsx` — human milestone rail rendered as a collapsible section above the feed (open while running, collapsed after completion).
- `components/execution/ResourceBar.tsx` — persistent secondary resource line in the run header (cost/budget, elapsed, latency, tokens, tools, switches). Subtle by design.
- `components/execution/ApprovalCenter.tsx` — approval queue wired to the real backend (`snapshot.execution.pendingApprovals`, legacy `snapshot.approvals` fallback; `POST /api/runs/:id/approvals/:approvalId/approve|deny`). Approve/Deny call the live endpoints; single-use/expiry enforced server-side. Empty state + real tool-permissions matrix (registry status × run toolPolicy) when nothing is pending. Nothing is auto-approved.
- `components/outcome/OutcomeCard.tsx` — outcome-first completion hero (TASK COMPLETED + summary + stats + Proof list + Review changes / View evidence / Continue task). Continue starts a linked follow-up run (`Follow-up: <title>`) because completed runs are backend-read-only (409 on send) — history is never rewritten.
- `components/outcome/EvidencePanel.tsx` — proof of result from real snapshot state only (outcome, tools, changes, decisions, verification incl. metered cost). Missing categories render as "not recorded", never invented.
- `components/decisions/WhyPanels.tsx` — Why-included (context relevance), Why-used (memory confidence/source), Why-switch (backend reason+factors). Display-only; no routing logic in React.
- `App.tsx` — boot (loads runs/models/tools/memory/evals, selects active run, loads snapshot), top bar (brand, LIVE/DEMO mode badge with `/api/health` fallback, connection pill, icon-only search/theme/inspector controls with hover tooltips, primary New Run), resizable three-panel shell, view router, toasts, drawer scrim. Panel tracks are built to match rendered children exactly (a static template would drop `<main>` into a 0px track when a panel is closed). Effective widths respect the viewport scale (1440/1280/1024/900/768/480/390, zero document h-overflow). Narrow screens (≤980px) start with both drawers closed so center stays primary; ≤560px compacts topbar actions so nothing clips.
- `components/icons.tsx` — one SVG icon family (16px, 1.7 stroke, round caps, currentColor). No raw Unicode glyphs as primary controls.
- `components/Tooltip.tsx` — hover-first tooltips (`Tip` + `shortcutLabel`): label plus shortcut on hover AND keyboard focus. Shortcuts live here, in the palette, and in Settings — never as permanent layout content.
- `components/LeftPanel.tsx` — New Run (tooltip shows ⌘N) + collapse, Recent runs (title + status dot + rel-time only; spend/model stay in the inspector; hover reveals an overflow menu with Copy run ID — no fake rename/delete, the backend offers none) / economics (Overview, Savings) / operations (Requests/Runs, Sessions, Prompts, Cache, Alerts) / Library (models, tools, memory, evals with live counts) / Workspace (Projects/Teams, Billing, Settings).
- `components/Center.tsx` — `RunHeader` (title, ONE status pill, contextual Stop/Retry, journey strip, secondary `ResourceBar`, preset/mode in subtitle), `MessageList` (dependency-free safe markdown: code blocks, tables, lists, quotes; pinned auto-scroll so history reading never jumps; streaming cursor; copy buttons; 150-message render cap; collapsible `ExecutionTimeline` above the feed; `OutcomeCard` + legacy compact `RunOutcome` completion card with real numbers only), `Composer` (textarea + task-mode select + Send/Stop/Retry; Enter-to-send, `/` focuses, Esc blurs; stays disabled on terminal runs with an honest hint — send would 409 — while `OutcomeCard → Continue task` offers the follow-up path).
- `components/Inspector.tsx` — tabbed inspector: **Overview** (outcome/focus, health, current model, cost, tools, approvals), **Decisions** (why, routing, switches, decision log), **Resources** (context + why-included, cache, memory + why-used, latency, history), **Evidence** (evidence panel, changes, replay, compare), **Technical** (execution trace + runtime state). Arrow-key tablist, one panel family per tab (no duplicate section ids).
- `components/NewRunDialog.tsx` — task-first: "What do you want done?" → task mode → "How should I work?" (real backend presets with consequence copy) → Tools (auto = Autonomous / readonly = Restricted, with plain-language autonomy hints) → Budget upfront → Advanced runtime settings (model, switching, compaction) collapsed. No fake per-tool checkboxes or success criteria; only `preset/budget/preferredModel/allowSwitching/allowCompaction/toolPolicy` are sent.
- `pages/pages.tsx` — Models (sort: quality/cost/latency/context/reliability + status filter, cards with text stat labels), Tools (enabled filter, BLOCKED/RUNNING states), Memory (scope filter, importance sort, cards), Evaluations (search + sort, pass/fail, empty by design), Settings (Providers & runtime from real `/api/health` + `/api/config`, General, Appearance, Composer defaults, Shortcuts reference; panel widths/visibility are workspace state with AUTO-SAVED note, never settings toggles; secrets never rendered).
- `components/CommandPalette.tsx` — Ctrl/⌘+K search across runs, models, tools, memories plus actions (New Run ⌘N, Focus composer `/`, Toggle inspector, Switch theme) and contextual Stop (Esc)/Retry that appear only when relevant. No invented per-item shortcuts. Arrow/Enter/Esc keyboard flow. All hooks above the closed-state early return (regression-tested).

## State management
- `state/store.tsx` — `RuntimeProvider` with `useReducer`. **Server state** (runs, snapshot, models, tools, memory, conn, sending) and **UI state** (view, settingsAnchor, panel widths/visibility, expanded sections, selection, queries, palette) are separate slices. Panel geometry persists to `localStorage` (`orchestra-panels-v1`: widths + collapsed state; transient run state is never persisted as configuration). Progressive disclosure by default: health/model/why/context/cost/tools open; switches/routing/latency/cache/memory/decisions/history/trace/changes collapsed. `applyEventToSnapshot` is a pure function (unit-tested) mapping every SSE type to snapshot updates; reducer dedupes by `seq`.
- `hooks/useEventStream.ts` — `EventSource` on `/api/runs/:id/events?since=<lastSeq>`, exponential-backoff reconnect, `: ping` keepalive tolerance. `freshnessLabel` → LIVE (<30s) / STALE / DISCONNECTED / UNKNOWN; stale banner shows last-update timestamp and data is never presented as current.

## Runtime event handling
Snapshot first (`GET state` → `lastSeq`), then authenticated SSE stream with `since` replay (backend keeps a 500-event per-run buffer). `response.delta` appends native provider deltas for LIVE adapters; DEMO emits one labelled completion event and never pretends to be provider streaming. `response.done` finalizes it. Tool start/finish flips per-tool `lastStatus` and appends mono tool rows. Model/routing/context/cache/cost/memory events update only their slice. Session 3 events (`plan.created/updated`, `tool.approval_required/approved/denied/timed_out`, `approval.requested/decided`, `changeset.created/applied/rolled_back`, `verification.started/passed/failed`, `episode.started/completed`, `execution.recovery_*`) render as trace + change headlines; authoritative plan/approval/changeset/episode state always comes from `snapshot.execution` (server source of truth, never reconstructed locally).

## API layer
`src/api/client.ts` — the only module that calls `fetch`. Authentication is a server-managed **HttpOnly session cookie** sent via credentialed fetch — there is intentionally no browser-local bearer token or `localStorage` credential path (`getApiToken/setApiToken` were removed; `me()` reports session status). Clients expose `health/config/getRuns/createRun/getRun/getState/sendMessage/cancelRun/retryRun/forkRun/duplicateRun/compareRuns/getModels/refreshModels/getModelChanges/getTools/getMemory/getEvaluations/getProviders/connectProvider/testProvider/disconnectProvider/getPresets/getRuntimeSettings/saveRuntimeSettings/getExecution/listApprovals/decideApproval/continueRun/getPlan/getChangesets/verifyRun/streamUrl/signup/login/logout/me/getProjects/createProject`. Cancel/retry/pause-equivalent controls call backend endpoints only. 401/403 responses throw explicit errors (never silent); Settings shows an **account session** status row and notes env-configured API tokens are for non-browser callers.

## Three-panel design
Resizable CSS grid (default 264px · 1fr · 380px, ranges 180–380 / 300–520, viewport-clamped); center max-width 860px; inspector is a prioritized card stack with collapsible sections. Draggable overlay resize handles (mouse + touch + keyboard arrows/Home/End, `role=separator` with values); widths + collapsed state persist (`orchestra-panels-v1`); collapsed panels get a rail affordance so users are never trapped. Narrow screens (<980px): left/right become slide-over drawers with scrim + Esc, center stays primary.

## Performance strategy
Normalized snapshot, single reducer pass per event, `useMemo` on trace/timeline, SSE deltas mutate only the streaming message, trace/changes capped (200/100), sparkline slices last 24 samples, resize dispatches width-only patches (no full-tree recompute beyond context propagation), no full-page refreshes.

## Responsive / accessibility
Verified no document h-overflow at 1440/1280/1024/900/768/480/390. Keyboard: Enter-to-send, Shift+Enter newline, `/` focuses composer, ⌘/Ctrl+K palette, ⌘/Ctrl+N new run, Esc closes drawers/dialogs (palette handles its own), resize handles are keyboard-operable, all sections are `<button>`-toggled with `aria-expanded`, feed is `role=log aria-live=polite`, drawers labelled, focus-visible rings, semantic colors with text labels (not color-only), `prefers-reduced-motion` disables animation, tooltips appear on keyboard focus as well as hover.

## Testing
`npm test` (vitest, jsdom): runtime, inspector, palette, center, session4, settings, landing, models, product, and session-security coverage — all passing. `npm run build` (tsc + vite) passes. Backend-verified live: create task → send → COMPLETED with metered cost + routing decision + tool calls; send-to-terminal 409 and retry-completed 409 confirm the disabled-composer + Continue-task design; `/compare` 200 confirms the Evidence → Compare flow; SSE replay carries `seq`.

## OrchestraAI product layer
- Brand: OrchestraAI everywhere (console, title, favicon, health `service: orchestraai`, `OPENROUTER_APP_NAME=orchestraai`). Identity is orchestration green (primary) + calm sky (secondary) on warm neutrals — no generic AI-purple. Theme key `orchestra-theme` (migrates `aar-theme`); **light-first** friendly design system, warm dark theme one toggle away (`?theme=dark|light` deep-link supported, plus `?view=models|tools|memory|evals|settings|run`).
- Run header carries a **journey strip** (Task → Context → Model → Execute → Done) derived only from real snapshot state (`journeySteps` in `Center.tsx`, unit-tested). Terminal runs show a **FINAL** pill (topbar + inspector) instead of STALE — completed history is final, not ageing; only a real stream error still shows DISCONNECTED.
- Terminal-run honesty: composer disables on completed/cancelled/failed with a contextual hint (send would 409); cancelled copy points to New Run (retry/cancel-resume are backend-rejected); failed copy points to Retry.
- Settings gained a **Providers & runtime** card backed by real `GET /api/health` + `GET /api/config`: LIVE/DEMO, provider id, credential presence (never values), discovery state, run guardrails — with honest loading/error states.

## Runtime integration contracts
1. Real `GET /api/runs/:id/state` snapshots in the exact `RuntimeSnapshot` shape (especially `routing.decision.factors`, `context.items[].status`, `cache.recent`).
2. Live SSE at `/api/runs/:id/events` with `seq`, `since` replay, and `price.updated` / `memory.write` / `model.switched` events.
3. `POST cancel/retry`; pause/resume is intentionally not exposed because durable resumability is not supported in the current V1.
4. `GET /api/evaluations` real metrics (page already renders any array it returns).
5. Auth for any dangerous actions; frontend must never receive provider secrets — keep redaction server-side (`memory.snippet` must stay safe to render).
